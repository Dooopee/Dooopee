# Profile design — DOOOPEE / ODD PRACTIC

## Назначение

Публичный профиль показывает текущий приоритет ODD PRACTIC и один существующий продукт — NEXEL. Тексты намеренно не выдают продуктовые планы за реализованные возможности.

## Визуальные правила

- Палитра: **#0B0B0B**, **#111111**, **#414141**, **#AFAFAF**, **#F5F5F5**. Оттенки — только нейтральные, без цветных акцентов.
- Композиция: один сильный титульный блок, одна схема тренировочного процесса, реальный скриншот публичного проекта, короткие смысловые секции.
- Типографика внутри SVG: Arial/Helvetica и системный моноширинный fallback. В README — стандартная GitHub-типографика.
- Никаких выдуманных KPI, stars, языковой статистики, ссылок на несуществующие docs и кнопок, имитирующих функциональность.
- Рекламные лозунги заменяются описанием сути и текущего статуса.

## Motion

- \`odd-hero.svg\`: сдержанное появление заголовка, медленное движение прицельных элементов и вращение технической дуги.
- \`odd-method.svg\`: течение линии между четырьмя этапами тренировочного цикла.
- Мобильные версии: отдельная композиция, а не уменьшенная широкая карточка.
- \`prefers-reduced-motion: reduce\` выключает CSS-анимацию. Без JavaScript, внешних библиотек и зависимости от третьих сервисов.
- Контент остаётся читаемым, если браузер или GitHub отключит анимацию.

## Ограничения платформы

GitHub README — документ на GitHub Flavored Markdown, а не полноценный сайт. Здесь допустимы простые раскрывающиеся секции \`<details>\`, ссылки, таблицы и изображения. Рабочие JS-компоненты, произвольные обработчики событий, аудиоплееры и сложные hover-взаимодействия в README не поддерживаются.

## Факты и безопасность

- Репозиторий \`Dooopee/ODD-PRACTIC\` является приватным. Не помещать в публичные assets внутренний код, скриншоты закрытых экранов, токены или невыпущенные материалы.
- На момент подготовки оформления у проекта только стартовый README: \`# ODD-PRACTIC\`. Направления тренировок описаны как **план**, не как готовые возможности.
- Ссылка на приватный репозиторий в основном профиле умышленно не используется: сторонним пользователям она показывала бы 404.
- Скриншот NEXEL взят из существующей публичной галереи.
- Страница профиля меняется только после ревью предлагаемого Pull Request. Изменения в \`main\` не выполняются автоматически.

## Проверка перед merge

1. Открыть README в branch/PR через GitHub и проверить, что обе SVG отображаются.
2. Открыть GitHub в светлой и тёмной теме: контраст и порядок секций должны сохраняться.
3. Проверить на узком экране, что используются мобильные версии SVG.
4. Включить reduced motion в ОС/браузере и убедиться, что чтение не зависит от анимации.
5. Проверить ссылки на публичные репозитории, релизы и текущий дизайн-документ.
6. Убедиться, что приватный проект нигде не представлен как выпущенный продукт.
7. После любого существенного изменения статуса ODD PRACTIC обновить формулировки в основном README.

## Вне зоны управления этим репозиторием

Аватар аккаунта, bio и закреплённые репозитории настраиваются в GitHub Account Settings/Profile. Изменение README не меняет их автоматически.
